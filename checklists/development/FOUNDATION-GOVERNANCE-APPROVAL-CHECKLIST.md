# Foundation and Governance Approval Checklist

## Foundation

- [ ] Project Charter reflects the intended product and target groups.
- [ ] Scope clearly separates Version 1.0 from later profiles.
- [ ] Principles are compatible and pragmatic for solo developers.
- [ ] Glossary definitions are consistent across the repository.
- [ ] Content architecture and document catalog match the repository.
- [ ] Version 1.0 acceptance criteria are testable.

## Governance

- [ ] Normative keywords are unambiguous.
- [ ] Document statuses and transitions are complete.
- [ ] Metadata fields are sufficient and validated.
- [ ] Versioning distinguishes document, standard, tag and publication versions.
- [ ] Change types and compatibility rules are complete.
- [ ] Exceptions distinguish Not Applicable, Open and Approved Exception.
- [ ] Alignment distinguishes prepared artefacts from executed evidence.

## Validation

- [ ] Document metadata validator passes.
- [ ] Markdown link validator passes.
- [ ] Governance requirement validator passes.
- [ ] Governance requirement index is current.
- [ ] No Blocker finding remains.
- [ ] Approval Record identifies the reviewed commit.

## Decision

- [ ] Approved
- [ ] Rework required
- [ ] Rejected
