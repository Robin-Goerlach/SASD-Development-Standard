# Initial Lessons Learned – SASD Mail Workbench

1. Architektur- und Produktreife müssen getrennt bewertet werden.
2. Ein sichtbares Testportfolio ist erst mit konkretem Commit und grünen Ergebnissen belastbare Evidenz.
3. Profilanwendbarkeit kann sich im Projektlebenszyklus ändern; Desktopanforderungen sind vor der GUI nur teilweise relevant.
4. Bei Mailverarbeitung sind Recovery und Trust Boundaries wichtiger als frühe Featurebreite.
5. Ein komplexer Pilot soll vorhandene professionelle Strukturen prüfen, nicht zusätzliche Bürokratie erzeugen.
