# Glossar

| Begriff | Bedeutung |
|---|---|
| Abweichung | Bewusste Nichterfüllung oder alternative Umsetzung einer Anforderung mit dokumentierter Begründung, Risikoabwägung und gegebenenfalls Genehmigung. |
| ADR | Architecture Decision Record; dauerhaft dokumentierte Architekturentscheidung mit Kontext, Alternativen und Konsequenzen. |
| Approved | Freigegebener Dokumentstatus. Nur Approved-Dokumente können verbindlicher Bestandteil einer veröffentlichten Standardversion sein. |
| Artefakt | Erzeugtes oder gepflegtes Arbeitsergebnis, beispielsweise Dokument, Binärdatei, Testbericht, Paket oder Publikation. |
| Compliance | Nachvollziehbarer Grad der Übereinstimmung eines Projekts mit einer benannten Standardversion, ausgewählten Profilen und einer Qualitätsstufe. |
| Core Standard | Technologieunabhängiger Kern des SASD Development Standard. |
| Dokument-ID | Stabile repositoryweit eindeutige Kennung einer Dokumentrolle. |
| Draft | Aktiver Arbeitsentwurf ohne verbindliche Wirkung. |
| Informativ | Erläutert, begründet oder zeigt Beispiele, ohne eigenständig verbindliche Anforderungen zu setzen. |
| Normativ | Enthält verbindliche Definitionen, Anforderungen oder Prozesse. |
| Planned | Vorgesehene Dokumentrolle oder Funktion, die noch nicht fachlich ausgearbeitet ist. |
| Profil | Ergänzt und konkretisiert den Kernstandard für eine Technologie, Plattform oder Projektart. |
| Proposed | Inhaltlich weitgehend vollständiger Freigabekandidat, der noch nicht verbindlich ist. |
| Qualitätsstufe | Definiert den angemessenen Mindestumfang der Anforderungen: Minimum, Recommended oder Production. |
| Referenzimplementierung | Konkretes Projekt, das die praktische Anwendung und Eignung des Standards demonstriert. |
| Source of Truth | Verbindliche Quelle, aus der abgeleitete Darstellungen oder Exporte erzeugt werden. |
| Standardversion | Veröffentlichter oder geplanter Gesamtstand des SASD Development Standard. |
| Unterstützendes Artefakt | Vorlage, Checkliste, Prompt oder Tool, das die Anwendung des Standards erleichtert, ohne selbst automatisch neue Anforderungen zu erzeugen. |
